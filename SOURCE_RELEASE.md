## Contents and build

- `Code`: Managed Doom, host/network/UI adapters, MeltySynth and project file.
- `Editor`, `ProjectSettings`, `Assets/game.scene`, `doom_port.sbproj`: editor,
  scene and package definitions. Compiled caches are regenerated by s&box.
- `Assets/doom`: three Freedoom/FreeDM IWADs, soundfont, licenses and credits.
- `WebShell`: external launcher's editable HTML, CSS and JavaScript, with its
  upstream notice. See its README for external services and asset limitations.
- `tests/Regression`: independent gameplay regression harness and stubs.
- `tools`: release inventory/notice verification; no private research required.

Install the s&box editor and .NET 10 SDK. Open `doom_port.sbproj` in the editor,
let it generate local project files if necessary, open `Assets/game.scene` and
press Play. The game uses a separately hosted web launcher; see below for the
offline engine check. For command-line C#/Razor compilation:

```powershell
dotnet build Code/doom_port.csproj -p:SboxInstallDir="C:/path/to/sbox"
```

For an SDK with its managed assemblies in a different directory, set
`-p:SboxManagedPath="C:/path/to/managed"`. The project does not ship these SDK
assemblies. Sandbox.Generator is required; CodeUpgrader is used when available.
The inspected source targets .NET 10 and C# 14. Dependency versions must match
the editor used to publish; native runtime compatibility is not inferred from
a successful C# build.

```powershell
python tools/verify_release_assets.py
dotnet run --project tests/Regression/Regression.csproj -- .
```

The test harness requires .NET 9, reads the bundled Freedoom file, and exercises
engine saves/input/multiplayer helpers without credentials or a live backend.

## Services and private information

The default game uses public HTTP endpoints for the web launcher, leaderboards,
analytics and bug reports. Their client models and requests are in
`Code/ManagedDoomHost`; browser requests are in `WebShell/js`. To use your own
services, replace those endpoint constants with your URLs and implement the
documented-by-code request/response contracts. Private databases, passwords,
SSH credentials, deployment settings and logs are not required build inputs
and are excluded. This release does not recreate the production backend.

For a launcher-independent local engine check, change `StartInShell` in
`SboxManagedDoomPanel.razor` to false, then run the scene. That is a modified
test build, not the exact tagged release. Hosted features will still require
their services. Do not present this as a complete offline clone of the website.
